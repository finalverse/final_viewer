Updated 2026-10-08 for the MutSea platform direction. Execute this phase now; do not execute 4C in parallel. Read the current repository instructions, Phase 4A validation, platform direction and source before editing.

MutSea is the canonical AI-native spatial runtime/platform. Finalverse is the flagship consumer experience. Blender is an authoring IDE, not a world database. Preserve the existing renderer, Phase 4A interface, mature protocols and Phase 2/3 world/citizen identities and history.

1. Record exact Git states and preserve unrelated work. Establish a running local sandbox and before screenshots/performance. Inspect the actual inventory, appearance, asset delivery and renderer capabilities.
2. Fix the avatar cloud root cause. Provision a fresh private development account through inherited services, verify required body/outfit/inventory assets and persistent appearance, then prove logout, simulator/viewer restart and relogin. Do not hide the cloud or claim a placeholder is a complete avatar.
3. Create original or verified open-licensed content in a separate Finalverse Studio surface. Keep editable Blender sources, exported runtime assets, semantic/provenance manifests, deterministic build instructions, thumbnails and measured LOD/collision/texture budgets. No hard Blender dependency in the client.
4. Renovate Harbor toward a warm, inviting coastal community: arrival, recognizable landmark, waterfront, pavilion, home/garden, creator workshop, seating, vegetation and coherent Day/Golden Hour/Night presets. The supplied illustration is art direction, not delivered evidence.
5. Develop a recognizable Lumi body/outfit with a suitable skeleton, movement and readable silhouette. Preserve canonical Lumi identity, home/memory/navigation bindings. Evaluate every avatar/outfit/asset/building/place/environment as reusable MutSea Starter Library content. Do not create a second citizen or replace existing homes by deleting IDs/history.
6. Define versioned compositional packages with mandatory semantic types, names, descriptions, affordances, relationships, policy and rights/provenance. Pin dependencies and payload hashes. Separate template IDs from instantiated world IDs. Preserve existing IDs through an explicit, reversible renovation plan.
7. Import only validated approved content through deterministic MutSea adapters that reuse asset/inventory/scene services. AI emits WorldPlan proposals; policy and authorized transactions execute changes and record WorldLine. No arbitrary model-generated Python, UI automation for world operations, or direct editor mutation of canonical state.
8. Benchmark equivalent cameras/settings before and after: FPS/frame time, object/triangle/draw-call counts, memory, loading time and payload size. Record unavailable measurements honestly. Exercise arrival, Lumi, home, garden, pavilion, waterfront, creator area and day/night views in the actual viewer.
9. Recheck login, movement, selection, nearby inspection, conversation, AI preview/apply/Undo, Friends/Me/inventory and citizen persistence/home/navigation/garden. Save unaltered actual viewer screenshots separately from Blender renders. Document limitations and coherent local milestones; do not push without authorization.
